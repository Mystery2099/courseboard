## Testing notes

- **Demo content for search lives in the shared Atlas database**, so production and previews show it too. Added November 16, 2026: 31 accounts (`@demo_ana`, `@demo_ben`, `@demo_chloe`, `@demo_dev`, `@demo_elena`, `@demo_farid`, 24 `@demo_student_NN`, and one without a profile), 41 history entries, and 34 posts, 26 of them "Midterm prep" threads for paging. Every document carries `demoSeed: 'search-2026-11-16'`; to remove it, first delete the `replies` whose `postId` is one of the seeded posts, since real accounts can reply to them, then delete by that field from `users`, `academicHistories`, and `posts`. The accounts have no Clerk identity and can't sign in.
- **The CSP is fixed at build time.** It takes Clerk's Frontend API host from `PUBLIC_CLERK_PUBLISHABLE_KEY` during `pnpm build`, so changing Clerk keys needs a rebuild. Render rebuilds when environment variables change. CI builds with the placeholder key and logs a warning; that build is never deployed.
- **Clerk needs extra CSP sources:** its Frontend API host, `cdn.protect.clerk.com` for the bot-protection script and `*.client.protect.clerk.com` for the loader it fetches, `*.protect.clerk.com` on any port for its probes and frames, `img.clerk.com` (now covered by `https:` in `img-src`, which link previews need), and `challenges.cloudflare.com`. They're in [`server/ContentSecurityPolicyDirectives.js`](../../server/ContentSecurityPolicyDirectives.js).
- **Clerk telemetry is turned off** in the root layout instead of allowed in the CSP. Clerk sends it only from development instances, and it skips automated browsers, so checking it in headless Chromium means hiding `navigator.webdriver`.
- **Running the production build over plain HTTP locally:** adapter-node assumes HTTPS unless `PROTOCOL_HEADER` names a header, so Clerk's handshake redirects to `https://localhost` and fails. Start with `PROTOCOL_HEADER=x-local-proto` and send `x-local-proto: http` on requests to localhost, or use `pnpm dev`.
